# Milo — 90 Day English Challenge

A local-first React Native app (Expo SDK 57, TypeScript strict, Expo Router). No backend: all
content is bundled, all progress lives in SQLite on the device.

## Commands

```bash
npm start                 # Expo dev server
npm run ios               # dev server + iOS Simulator
npm run typecheck         # tsc --noEmit
npm run lint              # expo lint (ESLint 9, eslint-config-expo)
npm test                  # jest-expo unit tests (domain logic + content validation)
npm run verify            # typecheck + lint + test
npm run assets:optimize   # re-optimize assets/ from assets-original/ and regenerate the registry
npm run assets:check      # validate assets/ against assets-manifest.json
npm run assets:registry   # regenerate src/constants/assets/registry.generated.ts
```

## Structure

```
src/
  app/                  Expo Router routes (thin: they re-export feature screens)
    (tabs)/             Today · Journey · Friends · Profile
    settings.tsx        pushed screen
    dev-tools.tsx       __DEV__ only (redirects in production)
  components/
    ui/                 primitives: AppText, Button, IconButton, ProgressBar, Screen, Card,
                        Divider, Badge, Avatar, LoadingState, PressableScale
    AssetImage · EmptyState · ErrorState · navigation/AppTabBar
  constants/
    challenge.ts        challenge rules (90 days, weekly exams, XP bonuses)
    assets/             generated asset registry + asset types
  data/
    content/            bundled content: chapters, 90-day schedule, achievements, lessons, friends seed
    db/                 SQLite connection + versioned migrations
    repositories/       repository interfaces + local (SQLite/content) implementations
    query-keys.ts       every TanStack Query key
    repository-provider.tsx
  features/             feature modules (screens, feature components, queries, domain logic)
    achievements · challenge · dev-tools · friends · journey · profile · progress · quests · settings · today
  hooks/ lib/ providers/ schemas/ services/ stores/ theme/ types/ utils/
assets/                 production assets (generated by the asset pipeline)
assets-original/        untouched originals — source of truth for the pipeline
scripts/                asset pipeline + asset registry generator
```

## Data layer

- **Repositories** (`src/data/repositories`) are interfaces; the local implementations read bundled
  content and SQLite. Swapping in an `Api*Repository` later requires no screen changes.
- **TanStack Query** owns all data access; `Zustand` only holds global client preferences
  (sound/haptics) and dev switches.
- **Zod** validates content, database rows and persisted settings; all domain types are `z.infer`.
- **Use cases** (`features/progress/use-cases.ts`) compose repositories: completing a quest awards
  XP once, evaluates achievements and returns everything a reward moment needs.
- `queries.ts` inside each feature exposes the hooks; keys live in `data/query-keys.ts`.

## Assets

`src/constants/assets/registry.generated.ts` is generated from `assets-manifest.json` — the app
never calls `require()` for an asset directly:

```ts
import { mascots, badges, quests, sounds } from '@/constants/assets';

<AssetImage asset={mascots.idle} width={120} />;
playSound('questComplete');
```

Each entry carries intrinsic size, alpha and the review status from `ASSET_MANIFEST.md`.
Missing assets are listed in `missingAssets` (currently `quest-grammar.svg`).

## Sound & haptics

- `playSound('correct')` — one reusable player per sound, created once; respects the iOS silent
  switch and mixes with other apps' audio.
- `triggerHaptic('questComplete')` — semantic patterns, subtle by default.
- `playFeedback('dayComplete')` — the sound + haptic pair for one app moment (single source of truth).
- Both honor the user's settings (`src/stores/settings-store.ts`).

## Development tools

Profile → Developer tools (visible only in `__DEV__`): change the current day, complete or reset
quests, set the streak, add XP, toggle achievements, simulate a weekly exam or Day 90, empty or
restore friends, simulate offline, play every feedback event and haptic pattern, reset local data.

## Conventions

- No hardcoded colors, spacing or typography — use `@/theme` tokens.
- Screens stay thin: data via queries, logic in `logic/` or `use-cases.ts`.
- Expo Go compatible: no custom native code, no prebuild config beyond `app.json` plugins.
- Expo SDK 57 changed a lot: check https://docs.expo.dev/versions/v57.0.0/ before using an API.
